# 八卦排盘页（BaguaMobile）逻辑说明

页面文件：`src/views/BaguaMobile/index.vue`  
API：`src/api/bagua.ts`  
数据表：`he_luo_lookup`（多套矩阵，用 `matrix_code` 区分）

---

## 1. 页面整体结构

页面左右（或上下，窄屏时）两块：**河** 与 **洛**。每块结构相同：

```
┌─────────────────────────────────────────┐
│ 备忘框（顶部，localStorage，不入库）      │
├──────────────┬──────────────────────────┤
│              │ 第1行：查表得到的数字（只读）│
│   河 / 洛    │ 第2行：下拉选择            │
│   标题字     │ 第3行：下拉选择            │
│              │ 第4行：查表得到的数字（只读）│
├──────────────┴──────────────────────────┤
│ 结果区：8 行 × 最多 6 列（公式求和）      │
└─────────────────────────────────────────┘
```

输入区 4 行 × 4 列，对应 8 个位置键：

| 位置 | 键名 | 含义 |
|------|------|------|
| 第1行左→右 | `top0` `top1` `top2` `top3` | 上方查表数字 |
| 第4行左→右 | `bottom0` `bottom1` `bottom2` `bottom3` | 下方查表数字 |

第 2、3 行是用户选择，不直接进结果公式；它们用来算出第 1、4 行数字。  
其中 **第 3 行第 4 格** 还作为该区查表矩阵的 **横行（row）**。

---

## 2. 启动时加载什么

页面挂载后并行请求：

| API | 用途 |
|-----|------|
| `GET /bagua/lookup/hetu` | 河图：地支 × 天干（120 条）→ 河第 1 行 |
| `GET /bagua/lookup/hetu-cross` | 河图交叉：地支 × 地支（144 条）→ 河第 4 行 |
| `GET /bagua/lookup/luoshu-stem` | 洛书天干矩阵 → 洛第 1 行 |
| `GET /bagua/lookup/luoshu-branch` | 洛书地支矩阵 → 洛第 4 行 |
| `GET /bagua/almanac?year&month&day` | 今日黄历（当前查表**不再使用**年支） |

查表结果在前端建成 `Map<"row|col", number>`，键形如 `丑|庚`。

### 查表横行（核心规则）

河、洛各自用 **本区第三行第 4 个下拉** 作为矩阵 **row**：

- 河：`riverRow3Branches[3]`
- 洛：`luoRow3Branches[3]`

**未选**该格 → 该区第 1、4 行数字 **全部空白**（即使其它格子已选）。

对照查表图：右侧地支 = 横行；顶行地支 / 次行天干 = 纵列。  
例：选 `丑` → 行 `丑` × 列 `丑未` → `2`。

## 3. 河区逻辑

### 3.1 四行分别是什么

| 行 | UI | 数据来源 |
|----|-----|----------|
| 第 1 行 | 只读数字 | `hetu` 矩阵 |
| 第 2 行 | **天干**下拉 × 4 | 选项：甲乙丙丁戊己庚辛壬癸 |
| 第 3 行 | **地支**下拉 × 4 | 选项顺序：寅、卯、巳、午、辰、戌、丑、未、申、酉、亥、子；**第 4 格兼作查表 row** |
| 第 4 行 | 只读数字 | `hetu_cross` 矩阵 |

### 3.2 第 1 行查表（天干 → 数字）

前置：第 3 行第 4 格非空，记为 `rowKey`。

```
lookup(hetu, row = rowKey, col = 第2行所选天干)
```

例：第 3 行第 4 格选 `丑`，第二行选 `己` → `lookup(丑, 己) = 2`。

### 3.3 第 4 行查表（地支 → 数字）

前置：同上，`rowKey` = 第 3 行第 4 格（**不归一化**）。

```
lookup(hetu_cross, row = rowKey, col = 归一化(第3行所选地支))
```

**列归一化**（对应图一顶行「辰戌 / 丑未」同列）：

- `戌` → `辰`
- `未` → `丑`
- 其余地支不变

**行键不归一化**：图一右侧 `戌` 与 `辰`、`未` 与 `丑` 是不同行。

例：第 3 行第 4 格选 `丑`，同列也选 `丑` → `lookup(丑, 丑) = 2`。

### 3.4 河区数据流

```
第3行第4格 ──┐  (未选 → 整区数字空白)
             ├─→ hetu(rowKey, 第2行天干)              → 第1行 → top0..top3
第2行天干 ───┘
第3行第4格 ──┐
             ├─→ hetu_cross(rowKey, 归一化(第3行地支)) → 第4行 → bottom0..bottom3
第3行地支 ───┘
                    ↓
              结果区公式求和（见第 5 节）
```

## 4. 洛区逻辑

### 4.1 四行分别是什么

| 行 | UI | 数据来源 |
|----|-----|----------|
| 第 1 行 | 只读数字 | `luoshu_stem` |
| 第 2 行 | **天干**下拉 × 4 | 甲…癸 |
| 第 3 行 | **地支**下拉 × 4 | 子丑寅卯辰巳午未申酉戌亥；**第 4 格兼作查表 row** |
| 第 4 行 | 只读数字 | `luoshu_branch` |

### 4.2 查表规则

前置：洛第 3 行第 4 格非空，记为 `rowKey`；否则第 1、4 行全空。

```
第1行：lookup(luoshu_stem,   row = rowKey, col = 第2行天干)
第4行：lookup(luoshu_branch, row = rowKey, col = 第3行地支)
```

洛区**不做** 戌/辰、未/丑 列归一化（与河第 4 行不同）。

### 4.3 洛与河的差异小结

| 项 | 河 | 洛 |
|----|----|----|
| 第 2 行 | 天干 | 天干 |
| 第 3 行 | 地支（指定顺序） | 地支（自然十二支顺序） |
| 查表 row | 本区第 3 行第 4 格 | 本区第 3 行第 4 格 |
| 第 1 行矩阵 | `hetu` | `luoshu_stem` |
| 第 4 行矩阵 | `hetu_cross` | `luoshu_branch` |
| 列 戌/未 归一化 | 仅第 4 行 | 无 |

## 5. 结果区公式（河、洛共用同一套）

结果区有 **8 行**（标为一～八），每行最多 **6 格**。  
每个格子是若干 `top*` / `bottom*` 位置的**简单相加**；任一参与位置为空，则该格显示空。

记：

- `T0..T3` = `top0..top3`（输入区第 1 行）
- `B0..B3` = `bottom0..bottom3`（输入区第 4 行）

| 结果行 | 各格公式 |
|--------|----------|
| 一 | `T0+T1`；`T0+B0` |
| 二 | `B0+T0`；`B0+T1`；`B0+T0+T1`；`B0+B1` |
| 三 | `T1+T0`；`T1+T2`；`T0+T1+T2`；`T1+B0`；`T1+B1`；`T1+B0+B1` |
| 四 | `B1+T1`；`B1+T2`；`B1+T1+T2`；`B1+B0`；`B1+B2`；`B1+B0+B2` |
| 五 | `T2+T1`；`T2+T3`；`T2+T1+T3`；`T2+B1`；`T2+B2`；`T2+B1+B2` |
| 六 | `B2+T2`；`B2+T3`；`B2+T2+T3`；`B2+B1`；`B2+B3`；`B2+B1+B3` |
| 七 | `T3+T2`；`T3+B2`；`T3+B3`；`T3+B2+B3` |
| 八 | `B3+T3`；`B3+B2` |

加法与顺序无关。河、洛各自用自己的 `top*` / `bottom*` 算一套结果，互不影响。

## 6. 备忘框

- 页面顶部可编辑 `textarea`
- 内容存在浏览器 `localStorage`，键名 `bagua-memo`
- **不入库、不调 API**
- 输入时自动增高，保证文字全部可见
- 样式：红色、加粗，字号随视口放大（大屏平板更大）

## 7. 数据库矩阵一览

表名统一为 `he_luo_lookup`，字段：`matrix_code`, `row_key`, `col_key`, `value`(0–9)。

| matrix_code | 维度 | 条数 | 谁用 |
|-------------|------|------|------|
| `hetu` | 行=地支，列=天干 | 120 | 河第 1 行 |
| `hetu_cross` | 行=地支，列=地支 | 144 | 河第 4 行 |
| `luoshu_stem` | 行=地支，列=天干 | 120 | 洛第 1 行 |
| `luoshu_branch` | 行=地支，列=地支 | 144 | 洛第 4 行 |

初始化 SQL：

- `docker/init-db/03-he-luo-lookup.sql` → `hetu`
- `docker/init-db/04-luoshu-lookup.sql` → `luoshu_stem` / `luoshu_branch`
- `docker/init-db/05-hetu-cross.sql` → `hetu_cross`

---

## 8. 端到端示例（河）

假设：

- 第 3 行第 4 格 = `丑`（整区查表 row）
- 第 2 行天干随意已选 → 第 1 行按 `hetu(丑, 天干)` 出数
- 第 3 行四格均为 `丑` → 第 4 行四格均为 `lookup(丑, 丑) = 2`

清空第 3 行第 4 格 → 第 1、4 行全部空白。
